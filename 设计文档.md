## 1. 项目背景与目标

### 1.1 背景

原系统 `kc` 是基于 Go + Fyne 的桌面工具，用于比对 WMS 与「方仓 / 立库」的库存差异。现需用 C# WinForms 重新实现，统一到 .NET 技术栈，便于后续维护与二次开发。

> **变更说明（2026-09）**：后端数据库已迁移至 **SQL Server**，对客户端透明。经评估与实测，**客户端维持 HTTP 接口路线不变**（第 2、3、4.6、5、6、7 节全部有效）。实测结论：`http://<内网接口地址>:7880` 已连通，登录 / 库存差异接口均返回 `code:0`，契约基本未变（新增字段 `wms_location` 已决定忽略不展示，见 12.2）。直连数据库方案已否决，详见 1.4 节。

### 1.2 项目目标

- 功能 100% 对齐原 Go 版（v1.2.2）
- 架构保留原版分层思想（配置 / 模型 / 接口 / 转换 / 列定义 / 导出 / UI 分离）
- 复用原版已验证的并发安全与错误处理设计
- 产出可发布为单文件 exe 的 Windows 桌面程序

### 1.3 复现范围

**必须复现：**

1. 登录页：账号 / 密码、测试连接、API 设置入口、状态提示
2. 主界面：左侧筛选栏 + 右侧 12 列数据表格
3. 仓库筛选：全部 / 方仓 / 立库（单选）
4. 对比选项：对比冻结状态、对比过期日期（复选）
5. 刷新数据（异步、可取消）
6. 点击单元格复制到剪贴板
7. 导出 CSV（UTF-8 BOM、自动过滤全空列）
8. 退出登录 / 登录过期自动回登录页
9. 接口地址本地持久化
10. 窗口标题显示版本号

**明确不复现：**

- `internal/theme`（内嵌 Noto CJK 字体）→ WinForms 用系统「微软雅黑」
- `RunOnMain` 线程调度 → `async/await` 天然回到 UI 线程
- `epoch` 任务代际 → 改用 `CancellationToken`（请求可真正取消）

### 1.4 架构决策与变更记录

> **结论：客户端维持 HTTP 接口路线（原设计全部有效）；后端由原数据库改为 SQL Server，对客户端透明。**

**ADR-001（已采纳）数据访问：维持 HTTP API 路线**

| 项    | 内容                                                                                                                                                                                                                                   |
| ---- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 决策   | C# 客户端**继续通过 HTTP 接口**取数，不直连数据库                                                                                                                                                                                                      |
| 实测证据 | `<内网接口地址>:7880` 端口连通；登录返回 `code:0` + token；`/api/v1/stock/diff` 返回 `code:0` + 25 条数据；**抽查接口返回值与数据库原表数值一致**（如 `R21111300001` 的 `location=L001B7087`、`warehouse_expiry=20270315`），确认后端**已切换到新库**（`<立库数据库IP>` / `<方仓数据库IP>`） |
| 理由   | 后端接口已返回算好的 12 列结果（含 `diff_type`、`qty_diff`）；直连 DB 将被迫重建后端业务逻辑                                                                                                                                                                        |
| 影响   | 第 2、3、4.6、5、6、7 节**维持原设计**，不作改动                                                                                                                                                                                                      |
| 契约差异 | 实际响应多一字段 `wms_location`；`diff_type` 可能缺失；`warehouse_no` 仅 `asrs` 行出现（详见 12.2）                                                                                                                                                        |

**ADR-002（已否决）直连 SQL Server（只读）**

| 项    | 内容                                                                          |
| ---- | --------------------------------------------------------------------------- |
| 备选方案 | 客户端直连 `<方仓库>` / `<立库库>` 两库，仅 `SELECT`，客户端合并方仓与立库结果            |
| 否决原因 | 数据库原表无 `diff_type` / `qty_diff` 列，需重建过滤（`If_Back='0'`）、关联、冻结与效期判定；且列名口径反复未定 |
| 保留条件 | 仅当后端确认不再提供 HTTP 接口时重新启用，且须先取得后端 SQL / 源码                                    |

**参考资料（非客户端实现依据）**

- 12.3 记录了后端 SQL Server 两张原表结构与字段对照，**仅供排查 / 理解后端逻辑**，客户端不直接读取。

/// <summary>展示层转换：仓库代码↔中文、数字转字符串</summary>
public static class Converters
{
    public static string WarehouseLabelFromCode(string? code) => (code ?? "").ToLowerInvariant() switch
    {
        "fc"   => "方仓",
        "asrs" => "立库",
        "all"  => "全部",
        _      => "全部"
    };

    public static string WarehouseCodeFromLabel(string? label) => label switch
    {
        "方仓" => "fc",
        "立库" => "asrs",
        "全部" => "all",
        _      => "all"
    };

    public static string NumberToString(JsonElement n) => n.ValueKind switch
    {
        JsonValueKind.Undefined or JsonValueKind.Null => "",
        JsonValueKind.Number => n.GetRawText(),
        JsonValueKind.String => n.GetString() ?? "",
        _                    => n.ToString()
    };
}

### 4.6 Api/ApiClient.cs（对应 internal/api）

```csharp
public sealed class ApiClient
{
    // 静态单例：禁止每次 new，避免端口耗尽；不设全局超时
    private static readonly HttpClient Http = new() { Timeout = Timeout.InfiniteTimeSpan };

    private readonly object _lock = new();
    private string _baseUrl;
    private string _token = "";

    public ApiClient(string baseUrl) => _baseUrl = baseUrl;

    public string BaseUrl
    {
        get { lock (_lock) return _baseUrl; }
        set { lock (_lock) _baseUrl = value; }
    }

    public string Token { get { lock (_lock) return _token; } }

    public void SetToken(string t)        { lock (_lock) _token = t; }
    public void ClearToken()              { lock (_lock) _token = ""; }

    /// <summary>仅当 token 未被替换时才清空，避免旧 401 抹掉新会话 token</summary>
    public void ClearTokenIf(string old)
    {
        lock (_lock) { if (_token == old) _token = ""; }
    }

    public Task<string> LoginAsync(string username, string password, CancellationToken ct = default);

    public Task<List<StockDiff>> FetchStockDiffAsync(
        string warehouse, bool compareHold, bool compareExpiry, CancellationToken ct = default);

    public Task TestConnectionAsync(CancellationToken ct = default);

    private string FullUrl(string path) => BaseUrl.TrimEnd('/') + AppConfig.ApiPrefix + path;
}
```

**接口行为约定（逐条对齐源实现）：**

| 项              | 规则                                                                                                                                                                  |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 超时             | 各方法内 `CancellationTokenSource.CreateLinkedTokenSource(ct)` + `CancelAfter(对应超时)`；HttpClient 无全局超时                                                                   |
| URL 拼接         | `BaseUrl.TrimEnd('/') + "/api/v1" + path`                                                                                                                           |
| Login          | 入参空 → `ArgumentException("用户名和密码不能为空")`；HTTP 非 200 → 失败；`code != 0` → 用 `message` 报错；token 空 → “未返回token”；成功后 `SetToken`                                            |
| FetchStockDiff | 先快照 token，为空 → “请先登录”；`warehouse` 空 → `"all"`；query 携带 `warehouse` / `compare_hold` / `compare_expiry`（bool 小写 `true/false`）；Header `Authorization: Bearer {token}` |
| HTTP 401       | `ClearTokenIf(快照)` + 抛 `UnauthorizedException`                                                                                                                      |
| 业务 401/403     | `code == 401/403` 或 `message` 含 "token" → 同上                                                                                                                        |
| 其它状态码          | 抛 `ApiException($"获取库存差异失败: {status}")`                                                                                                                             |
| JSON 解析        | `System.Text.Json` 反序列化；数量字段落 `JsonElement`                                                                                                                         |
| TestConnection | 解析 BaseUrl 取 host；无端口按 scheme 补 `:443` / `:80`；`TcpClient.ConnectAsync` + 5s 超时；失败抛带排查建议的异常                                                                         |

### 4.7 Export/CsvExporter.cs（对应 internal/export）

```csharp
public static class CsvExporter
{
    /// <summary>纯函数：只写流，不弹对话框（对话框在 App 层）</summary>
    public static void Write(Stream output, IReadOnlyList<StockDiff> rows);

    public static string BuildDefaultFileName(string warehouseLabel) =>
        $"{DateTime.Now:yyyyMMdd_HHmmss}_{warehouseLabel}&WMS差异情况.csv";
}
```

规则：

1. `rows` 为空 → 由调用方提示“暂无数据”，本方法直接返回
2. **写 UTF-8 BOM**（`new StreamWriter(stream, new UTF8Encoding(true))`），保证 Excel 打开中文不乱码
3. 表头与数据行全部由 `TableColumns` 派生
4. 过滤全空列；若所有列都空，则保留全部列
5. 字段转义（RFC 4180）：含 `,` / `"` / 换行 → 双引号包裹，内部 `"` 转 `""`

## 13. 风险与注意事项

1. **数量精度**：数量字段禁止声明为 `double`，必须 `JsonElement` 或 `decimal`
2. **请求参数**：`request.md` 只写了 `warehouse`，但 Go 源码实际还发送 `compare_hold` / `compare_expiry`，**以代码为准**
3. **HttpClient 复用**：使用静态单例，禁止每次请求 new（避免端口耗尽）
4. **超时语义**：区分「用户主动取消」（静默丢弃）与「网络超时」（弹错误提示）
5. **DataGridView 性能**：万级以上记录启用 `VirtualMode`
6. **设置保存后**：必须清 token 并返回登录页，与原版行为一致
7. **CSV 编码**：必须写 UTF-8 BOM，否则 Excel 打开中文乱码
8. **接口契约已实测核对**：`http://<内网接口地址>:7880` 连通，登录与库存差异接口均返回 `code:0`；契约基本未变，实测差异见 12.2
   8.1 **后端已切库已验证**：抽查接口返回值与 `<立库数据库IP>` / `<方仓数据库IP>` 库中原表数值一致，确认接口数据源为新库，客户端可放心使用
9. **新增字段** **`wms_location`** **不展示**：响应多此字段（仅 `fc` 行），**已决定忽略**，模型无需映射；「WMS库位」列仍仅取 `warehouse_no`（`fc` 行空、`asrs` 行 `100B`），与旧 CSV 一致
10. **`diff_type`** **可缺失**：实测存在无 `diff_type` 的记录，反序列化后须默认空串，避免 NullReference
11. **不直连数据库**：数据库原表无 `diff_type` / `qty_diff` 列，直连将被迫重建后端业务逻辑，已否决（见 1.4 ADR-002）
12. **凭据与令牌明文传输（已记录，暂不处理）**：客户端与后端当前均为 HTTP（默认 `http://127.0.0.1:7880`，现场 `http://<内网接口地址>:7880`）。登录请求体中的工号/密码，以及后续请求的 `Authorization: Bearer <JWT>`，均未加密，同网段抓包即可获取，进而冒充该用户查询库存。
    - 现状来源：`AppConfig.DefaultBaseUrl` 为 http；`BaseUrlSetter.TryNormalize` 同时接受 http/https，但无强制。
    - 决策（2026-09-23 代码评审）：**暂不改动代码**，先与后端确认 TLS 能力，再在「后端启用 HTTPS / 客户端对非 https 地址二次确认 / 明确接受内网风险」三者中选定。
    - 过渡期约束：**勿在不可信网络中使用本客户端**；如需临时加固，优先推动后端启用 HTTPS。
13. **无自动重试（已记录，暂不处理）**：`FetchStockDiffAsync` / `TestConnectionAsync` 目前单次超时即失败，局域网抖动或后端重启期间需用户手动重试。是否加「幂等请求有限重试（≤2 次，仅超时/连接类异常）」待定，因其会改变失败耗时与日志行为，需产品侧确认。
